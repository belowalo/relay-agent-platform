# Runtime handoff

Branch: `codex/production-runtime`. Foundation: `76649286b51b39924261a876878efebf5e02f020`. Final SHA is reported in the delivery message.

Implemented: PostgreSQL legacy-domain DDL with tenant RLS/references; immutable revisions/run graphs; explicit read-only SQLite backup validation and transactional import; outbox dispatcher and lost-notification repair; authoritative atomic claims, leases, heartbeat fencing; bounded retries/dead letters; cancellation/timeout/drain; tenant capacity/backpressure and fair dispatch sweeps; durable version-bound schedules; all catalog control-flow kinds including child/loop suspension; exact-argument approval/action ledger; shared UsagePort hooks and resource limits; async workflow/run/recovery API and production composition.

Integration is required, not optional: security authenticate/authorize/usage/identity routes; connectors model/tool/secret adapters and metered fallback; knowledge retrieval/memory and domain routes; operations restricted roles/shared blobs/readiness/telemetry. Legacy evaluation execution, publication/chat/widget APIs and complete UI compatibility need their async integration modules; storage and import preserve their data but the old synchronous routes cannot be loaded in production. Missing ports fail closed. No production readiness claim, live-provider qualification, two-host staging, one-hour soak or P01 API load qualification is supplied by fixture tests.

New migrations: `0100-domain.sql`, `0101-runtime.sql`, `0102-dispatch.sql`, `0103-schedules.sql`. No frozen foundation migration or v1 contract semantics changed. Shared files: server/index.js and worker.js now select explicit local/production entrypoints; original code moved to local-index.js/local-worker.js. package.json adds runtime commands and formatting; bin/test-services.mjs includes runtime service qualification; the foundation startup test now checks missing production adapters rather than the old guard message. No dependency additions.

Production starts through `startProduction` in server/runtime/bootstrap.js, with RUNTIME_ADAPTER_MODULE and (worker) RUNTIME_DISPATCH_DATABASE_URL. Runtime ports are specified in [RUNTIME.md](../RUNTIME.md). Operations can compose health/drain around returned `{ready,close,worker,dispatcher}`; telemetry emits runtime.wall_ms, provider_ms and provider_sum_ms. Provider sum is not subtracted from parallel wall time; serial benchmark separates provider wait from application overhead.

Execution recovery preserves completed results and limits; uncertain effects never automatically replay. Stranded UsagePort reservations are checkpointed and block automatic resume until security's reconciliation. Known failed action occurrences are not blindly reissued. Approval context is authenticated at API boundaries and execute authorization is repeated after waiting. The database repository assumes its supplied context has already passed those application boundaries.

Commands: npm run build; npm run foundation:types; npm test; npm run test:browser; npm run format:check; npm run test:services.

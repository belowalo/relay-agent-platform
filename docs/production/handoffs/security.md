These are composition interfaces, not registered production HTTP routes or a converted production worker. Preserve the foundation production-startup gate until runtime integrates them. Existing local identities/data/usage remain SQLite until an explicit import; do not instantiate the legacy modules as a production fallback.

Provider results are `{value,usage:{tokens,costMicros}}`; unknown cost is null. Reserve a trustworthy maximum; cap provider input/output accordingly. 8. Operations composes proxy trust, HTTPS/origin/cookie/CSP/embed settings, outbound firewall, distributed per-IP/principal/workspace/application rate keys, bucket pruning, upload/parser OS isolation and global connection/process/stream caps. ## Settings, roles and dependencies

Use foundation production settings for database/Redis/blob/runtime/keyring configuration. OIDC adds `OIDC_ISSUER`, `OIDC_CLIENT_ID`, optional `OIDC_CLIENT_SECRET`, explicit comma-separated `OIDC_EMAIL_DOMAINS`, optional exact `OIDC_ENDPOINT_ORIGINS`, HTTPS `PUBLIC_ORIGIN`, `COOKIE_SECURE=true`. Private origins/CIDRs are trusted factory input, not a new blanket environment bypass. Session defaults are 24-hour absolute, 30-minute idle and 10-minute recent authentication. Budget policy is configured per workspace; no policy denies admission.

Suggested narrow grants (adapt names through operations): application role CRUD on tenant security repositories except audit (`SELECT,INSERT` only); `SELECT(id,email,disabled_at,mfa_enabled)` on accounts only; no sessions/password/MFA access. Identity role CRUD on global identity/session/challenge/recovery/OIDC repositories and append-only identity audit. Rate role CRUD on rate buckets only. No application role may own tables, bypass RLS, inherit migrator privileges or UPDATE/DELETE audits. Runtime domain tables need equivalent RLS. Call `DatabasePort.assertApplicationRole()` at startup.

Pinned dev dependency `@electric-sql/pglite@0.5.8` enables embedded PostgreSQL SQL/RLS tests. Existing runtime dependencies cover the implementation. Coordinator should combine manifest changes and regenerate the lockfile. Added commands: `npm run test:security` and `npm run test:security-services`. The live harness requires `SECURITY_TEST_DATABASE_URL` pointing to a disposable database named `relay_security_test...`; it applies migrations and creates narrow test roles, not production configuration. Browser tests support `RELAY_BROWSER_TEST_PORT` to avoid other running teams' servers.

## Shared diffs and contract proposals

- `server/index.js`: local route authorization, origin/rate/upload boundaries, actor propagation, application token scope/expiry/revoke and guest receipts, current publisher/inviter checks, stream revocation and sensitive audit. Reconcile with runtime's async route conversion; do not keep SQLite calls in production.
- `server/engine.js`: actor attachment/inheritance and revalidation at steps/lease/output boundaries. `server/providers.js`: authorization check before each fallback. Production must settle accepted provider work even when output is suppressed; the local accounting ordering is not sufficient.
- `server/tools.js`: endpoint-bound secret headers, authenticated no-redirect fetch, MCP follow-up destination checks, production SQL disable and local document ACL filtering. Reconcile with connector adapters/action execution.
- `server/knowledge.js`: optional actor argument and restricted-source candidate filter. Knowledge owns comprehensive ACL/export/cache enforcement.
- Security-owned legacy `auth.js`, `security.js`, `network.js`; manifest/lockfile; portable/free-port test helpers, affected platform/security/worker/runtime fixtures and browser publishing origin fixture. No frozen contract/ownership/acceptance document was edited.

Proposed contract clarifications: `actor.id` for application contexts is a scoped grant ID, not an application ID; typed document principals use `user:`, `application:` and `service:` prefixes. Usage unknown cost is null; absent usage is uncertain, not zero. Capacity exposes owner/generation acquisition/release as a security extension to runtime leases. Domain resource lookup and service-grant callbacks are trusted internal seams. HTTP error compatibility retains a string `error` alongside `errorCode`/`requestId`; coordinator should choose one shared production serialization. New methods extend frozen ports without changing their v1 methods. Document these amendments centrally at integration.

## Evidence, failure semantics and blockers

Exact commands/results are recorded in `../evidence/SECURITY.md`. Embedded PostgreSQL executes real SQL/RLS with narrow test roles, but serializes one connection; it does not qualify host/pool races, production privileges, network TLS or Redis. The dedicated live suite tests independent PostgreSQL pools, competing budget/capacity admissions and RLS context reset when credentials are available. Missing credentials cause the explicit command to fail, rather than silently pass.

Docker engine and disposable PostgreSQL/Redis credentials were unavailable in this environment. Real issuer/SMTP, object storage/KMS and isolated-parser infrastructure were also unavailable. Before release, operations supplies disposable services and narrow-role grants; runtime/knowledge/connectors integrate all hooks; verification runs live concurrent services, real OIDC/SMTP, revocation/ACL/export/stream and load acceptance against the exact combined commit. No paid resources were created or live private database changed.

Unknown-cost admissions default-deny. Uncertain calls retain ceilings; rejected result delivery still settles accepted work. Stale capacity cannot be stolen automatically. Recovery requires proving the old executor stopped and reconciling effects/charges before releasing capacity/holds. Provider ceilings are admission estimates, not a guarantee against higher provider bills. Key loss requires matching backup keys or upstream credential replacement/MFA re-enrollment; deleting a key can make retained backups unrecoverable. See `../usage-controls.md`, `../credential-recovery.md`, `../security-permissions.md` and `../security-assumptions.md` for procedures and the complete remaining-findings register.

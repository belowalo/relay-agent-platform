# Usage, budgets and resource limits

`createUsagePort` implements frozen UsagePort v1 using integer tokens and integer micro-USD (1 USD = 1,000,000 micro-USD). Provider/model are bounded diagnostic labels. `maximumCostMicros:null` and `costMicros:null` mean unknown, never free. The ledger groups actual/held usage by workspace, period, status, provider and model, and reports unknown-cost call counts separately from known cost sums.

`configure` is owner-only. Set `periodId`, `tokenLimit`, `costLimitMicros`, `allowUnknownCost`, `maxConcurrent` and `maxReservedTokens` explicitly. No policy means no metered admission. Period rollover is an explicit operator decision, not an automatic reset; outstanding reserved/uncertain calls block rollover. Lowering a budget prevents new admissions, but cannot undo accepted work. Unknown-cost admission is default-denied and cannot be enabled alongside a dollar cap.

`reserve` locks the workspace policy row and counts settled actual usage plus all outstanding reservations in the current period. Parallel calls cannot each spend the same remaining budget. Tokens/costs are validated safe nonnegative integers; aggregate comparisons use BigInt. Per-call token ceilings are bounded by policy. `settle` is idempotent only for the same reservation and exact reported usage; a conflicting settlement fails. `release` is idempotent for a known non-executed reserved call and refuses settled/uncertain calls. Settlement remains possible after actor revocation so accepted work is accounted for.

`createRuntimeSecurity().metered` authorizes, reserves, reauthorizes after budget-lock waits, calls the provider outside a transaction, settles and reauthorizes before returning output. Any call exception is conservatively uncertain; it retains its entire reservation. Missing/invalid provider token usage is also uncertain. Reconcile stranded reservations from the provider's usage/request record before settlement; do not release solely because a timer expired. A result with known tokens and unknown cost records the null cost and retains a known cost ceiling if one exists. Unknown costs with no ceiling remain visibly unknown and prevent later dollar-cap admission in that period.

Real charges above the stated ceiling are recorded and audited as `usage.ceiling.exceeded`; never truncate the charge to make a cap appear satisfied. A dollar limit controls admission against trusted ceilings. It is **not** a guarantee against provider charges when pricing, input size, tool charging or cancellation behavior is unbounded. Use provider-side quotas and reconcile invoices. Report missing prices, missing usage and third-party surcharges explicitly.

Apply the wrapper to each model round and each fallback attempt separately, embeddings (ingestion and query), reranking, paid search/OCR/transcription, connector calls, evaluation/judge calls and child workflows. Use service-specific `provider` and `model` labels, and reserve zero tokens with a cost ceiling for tokenless metered calls. A cache hit records cache telemetry with no new provider charge. Do not settle a parent again for child usage already charged to the workspace. The legacy model/embedding paths retain their original accounting until runtime/knowledge/connectors compose these hooks; this branch alone does not make their old cost reports a production budget ledger.

`createCapacityPort` locks the same workspace policy row, limits active run slots, and checks `ownerId,generation`. A slot renewal must match its owner/generation and be unexpired. Expired slots remain counted and cannot be stolen automatically: prove the old executor stopped, reconcile effects, then release with the old fencing tuple. Waiting approvals should release capacity; resumption must reauthorize/reacquire. This conservative policy can block capacity after a crash, favoring safety over automatic oversubscription. Runtime remains responsible for signal cancellation, fencing result writes, execution/node/time/tool-round bounds, process limits and coordinated draining.

Distributed rate policies: login 20/15 minutes, account 40/15 minutes, API 300/minute, publication 20/minute, upload 10/minute, guest 30/minute, webhook 60/minute. The PostgreSQL upsert is atomic across instances. Compose both IP and authenticated workspace/principal/application keys, plus an account/email key for login attempts. Use the shared database clock. Set bounded proxy trust only for the deployed proxy; never trust arbitrary X-Forwarded-For. Prune expired buckets through maintenance and enforce connection/SSE limits at the proxy. The local adapter is deliberately single-process, capped at 10,000 keys and fails closed on capacity; it is not the distributed production limiter.

Uploads: one file, 15 MiB, bounded multipart fields/parts, validated PDF/DOCX signatures, 2 MB extracted text and a 15-second parser timeout. The local subprocess excludes inherited application secrets and caps the JavaScript heap at 128 MiB. Native allocations and operating-system access are not isolated by that heap limit. Production binary parsing is blocked until knowledge supplies an OS-isolated parser with CPU/memory/process/filesystem/network limits. Arbitrary user SQL is disabled under production settings; there is no eval/shell/arbitrary-code executor added by this branch.
